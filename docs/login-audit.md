# 登录审计

两套主题的日志页均提供「登录审计」视图，支持时间、账号、IP、UA、Request ID 和日志类型筛选。

- `type=7`：成功登录；普通用户只能查看自己的记录，管理员可查看全部。
- `type=8`：登录安全事件；仅管理员可见，结果分为凭证失败、拦截、等待 2FA 和内部错误。
- 成功与安全事件均记录来源 IP、UA、登录方式、请求 ID 和不含查询参数的路径；管理员还可查看 CF-Ray、直连对端 IP 和目标账号。
- 未认证事件的 `user_id=0`；输入账号及已确认目标放在 `other.admin_info`，不视为目标用户本人操作。
- 缺失或全空白 UA 不允许创建新登录会话，记录为浏览器环境异常；已有会话、账号绑定和 API key 调用不受影响。UA 可伪造，不能证明请求来自真实浏览器。
- 密码、密文密码、验证码、备用码、Cookie、Authorization 和 OAuth code 不进入审计字段；文本去除 NUL 并按字段限长。

## 查询

`GET /api/log/` 与 `GET /api/log/self/` 支持 `scope=login`：管理员查询类型 7、8，普通用户只查询自己的类型 7；其余类型、时间和来源条件继续取交集。

管理员的账号筛选覆盖成功账号、目标用户名和输入标识，沿用现有 LIKE 语义；其他诊断字段不会参与账号匹配。`other.auth_audit` 保存 `outcome`、`stage`、`reason`、`count`，聚合记录另含 Unix 秒级的 `window_start`、`window_end`。

## 写入与保留

认证事件同步写入，单次数据库操作最多 500 毫秒；写入失败时输出完整白名单 JSON 备份，不改变认证结果。前置重复拦截按分钟聚合，聚合落库总时限为 2 秒，超时剩余事件转为备份；退出时取消并等待在途批次，再落库剩余计数。

实际凭证校验失败逐条记录；聚合行的来源信息代表首条请求，请求数按 `auth_audit.count` 求和，分页总数表示记录条数。自动清理 90 天前的类型 8，不受风控中心开关影响，不清理类型 7 或消费日志。
聚合状态最多 2,048 个桶，溢出仅按原因计数，不保留单个来源。
